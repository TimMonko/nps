# Blog Post Plan

I am currently tasked with writing blog posts about the URSSI Early Career Fellowship that I received that has enabled me, along with the napari community, to start the napari sustainability initiative. The `blog_post_fellowship.md` should be used as a reference for the content of these blog posts, along with notes from community meetings documented in `blog_post_hack.md`. The former fellowship proposal provides more solid context, motivation, and plans for the project, while the latter hack notes are more disorganized so must be considered more broadly.

The blog posts will be to two different audiences, discussed in more detail in corresponding URSSI blog and napari blog sections below. Both blogs will have a section to introduce the general matter at hand -- the plugin sustainability initiative. I think a nice opportunity to take, since this is a blog written by me, to also explain *my* story with respect to napari, where I began as a plugin contributor before shifting to developer

Then, there will be sections identifying the trends observed prior to the start of the intiative, which will mostly consist of the broader points put forth in the fellowship proposal. It is important to emphasize that the outcomes of the current issues have included lack of trust in the napari ecosystem, and struggle for the project, community, and plugin developers and maintainers to move forward. Initially, there was a big initial push which included an immature plugin system, development of community tools and support, *and* many novice contributors to both Python, packaging, and napari. Since then, there was almost a stagnation, at least externally, with progress in the plugin ecosystem and this caused a "rift" to form between core napari and the plugin ecosystem, including a "stagnation" of guidance and community input. However, it is also worth mentioninng that the plugin system ecosystem is maturing, both internally and as a community, and *certainly so is napari*. Due to new funding, napari is reinvigorated, which *preceeds* this plugin sustainability. In particular *napari itself* is on a sustainability trajectory and considerable positive feedback has been received from the community -- BOTH veteran and novice users, core developers, and plugin developers.

Both blogs should conclude with the next steps being taken and the overall value this brings to the napari community *and* the broader scientific software ecosystem as a whole.

## Community Identified Challenges

- The nature of scientific software creation is that it is often done by domain scientists, who may not have the time, resources, or expertise to create sustainable software.
- There is a lack of knowledge of what should be a "core" contribution to napari, and what should be a plugin
- There is a lack of *discoverability* with plugins that could be improved with better tagging, communication, etc
- There is a lack of developer cooperation, especially across domains / "teams", that would help prevent duplication of effort
- At every meeting, the community has identified the desire for plugin-to-plugin communication. I.e. the desire that there is some kind of "io" possible between plugins
- At every meeting, readers (especially) and writers have been brought up as consistent pain points -- for both developers and end users. These often face dependency hell, as well as make environments difficult to solve.

## Community Identified Approaches and Goals

Perhaps a nice flowing thought: folks see core napari development as shepherds/stewards of the entire ecoystem, and don't necessarily see the deep project roots that it takes to contribute. at the same time, plugin developers are encouraged by the shepherding, and potentially rely on core napari development, even more than the napari core team is neither aware of, nor able to provide in the current situation. At the same time, the initial effort of the napari plugin sustainability project through community meetings has identified a great need and desire from the napari ecosystem to contribute *outside* of the efforts of the napari core team. I would even describe plugin developers as often seem the separate from, or perhaps attached to (i.e. dependent on) napari, without much input. This will take some sensitive careful framing, because the goal is to describe that the community *wants* to be involved in the change of these actions. Much of this desire to help (and not just need for change) can be seen in the Agenda of `blog_post_hack.md`. The community wants to volunteer time and effort to create tools for plugin developers to know if they are up to best practices (and this documentation/ standard needs to be made), volunteering to review and more to contribute to *other* plugins. Finally, there is a desire to volunteer maintainership of plugins. (One possibility within napari would be to create a napari-plugins organization which serves as the volunteer committee, and allows both external and internal input, to lower the barrier to entry to contributing to the napari project).

## URSSI blog styling

The URSSI blog will target the broader scientific software / computing community. This blog should highlight the generous support from URSSI and the Sloan Kettering Foundation. It should also highlight the importance of sustainability in scientific software, and how the napari community is working to address this issue. The reader is assumed to have *no* knowledge of napari nor the image visualization/ image analysis / plugin ecosystem. This audience is also not necessarily a Python language audience, because the reader may have familiarity with other languages used in scientific computing (but usually will understand Python at a basic level). Therefore, this blog should also lay the groundwork for readers to understand what napari is, the scientific imaging commmunity (potentially including, but not limited to bioimage analysis), and how the plugin system works.

## napari blog styling

The napari blog will target the existing napari community, including users, core developers, and plugin developers. This blog should highlight the importance of sustainability in the napari plugin ecosystem, and how the napari community is working together to address this issue. The reader is assumed to have *some* knowledge of napari, but may not be familiar with the details of the plugin ecosystem or the sustainability initiative. Therefore, this blog should also lay the groundwork for readers to understand the current state of the napari plugin ecosystem, the challenges faced by plugin developers, and how the sustainability initiative aims to address these challenges. This blog should also include a call to action and provide practical ways for the napari community to get involved in the sustainability initiative.
